# BDF/FIF选择与同目录导出

## 导出fdata.fif

在“原始BDF → 质控 / FIF”选择“从本机选择BDF（同目录保存fdata.fif）”，打开电脑上的源BDF。也可以粘贴完整路径；保留原浏览器上传入口，使用它导出时需补填同一BDF的完整路径。浏览器不会向网页提供普通上传文件的真实目录，程序不使用`fakepath`猜测目录。

点击正式导出后，主EEG采样率组保存为源BDF同目录的`fdata.fif`。保存前比较源BDF与分析副本的SHA-256，保存后按块核对FIF样本、通道、类型、坐标和注释。原BDF不改动。已有同名导出先完整备份到同目录`.fdata_versions/时间_编号/`，再更新当前版本。网页下载也使用`fdata.fif`名称；每次分析的本机缓存保留。

不同原采样率不能无损装进同一个MNE Raw：将EEG通道最多的组作为`fdata.fif`，其余组为`fdata_group2.fif`等，不自动上采样。组清单见同目录`fdata_export.json`。很大的FIF可有MNE分卷（如`fdata-1.fif`），需与主文件一起保留；本网页上传分析当前仅支持独立单文件FIF，分卷会明确拒绝，不能只上传第一卷。

## 导入格式

单份、多份、镇痛前后入口均有BDF/FIF单选勾选。每个入口必须且只能选一种，配对A/B也必须相同。切换会清空该入口的已选EEG与旧分析显示；运行期间不能切换。文件后缀与勾选值不符或多份混用时拒绝处理。evt仍使用`evt.bdf`，JSON仍是JSON，不属于EEG格式选择。

文件夹导入只从数字子文件夹寻找当前格式的确切文件名：BDF模式为`data.bdf`；FIF模式为`fdata.fif`。不把其他采样率组、旧版备份或分卷误当作新的时间段。evt及JSON的匹配方式保持原有规则。自动填入后仍可手动添加、移除、排序；FIF头由本机MNE读取时间。未保存可靠开始时钟的FIF可单份分析，但多份时间对齐/evt分析会明确报错，不能凭序号虚构真实间隔。当前应用导出的FIF保留原BDF未核实时区的本地时钟文本，不将其伪装为UTC。

## FIF标记如何影响分析

读取FIF时只使用类型为EEG且不在`info['bads']`中的通道；辅助信号仍在源FIF内。BAD注释所覆盖或触碰的分析片段不参与特征，滤波与重采样在每段未标记连续数据内分别执行，短到无法滤波的余段也不进入特征。对通道特异的BAD注释，目前保守地将其视为整段排除，以避免静默忽略局部坏段。零持续时间的BAD标记至少排除所处采样点对应的片段。后续特征分析仍执行表单所选的0.5–45 Hz带通、陷波与常规质控；导出原始FIF的流程本身不做这些处理。

单份FIF在原有特征图之外增加：

- `FIF复核_坏道标记.png`：红色列出已保存的BAD通道，其他通道也列出。
- `FIF复核_坏段与眼状态时间轴.png`：BAD为红色；已保存的EYES_open/closed为绿色；眼动及其他原始注释为黄色，标注原标签。
- `FIF复核_眼动通道与标记.png`：展示实际类型为EOG的原始信号，优先定位首个已保存的眼动/眨眼标记附近；无EOG时明确提示缺失。EOG未滤波，仅作极值包络显示，不自动确认眼动伪迹。睁闭眼标签只表示眼状态。
- `FIF复核_原始标记.csv`：完整相对起止时间、原始标签和涉及通道。

FIF质控未通过时，单份入口保留上述复核输出并说明未计算特征，不以坏道/坏段数据绕过质控。所有图供人工检查；没有标记不代表没有伪迹。
